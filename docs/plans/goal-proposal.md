# 첫 멀티 에이전트 목표 제안

상태: 사용자 논의 대기. 목표 생성/멀티 에이전트 실행/예약 작업 없음.

## 제안 목표
STory 프론트엔드 목업을 교수 시연에서 안정적으로 사용할 수 있게 개선한다. 기존 디자인을 유지하고 백엔드·AI 호출은 추가하지 않는다.

## 제안 완료 기준
- 저장 데이터 검증, 저장 실패 후 이전 결과 링크, 화면 전환 상태, 접근성의 확인된 문제 수정.
- 주요 화면/상태/저장 경계를 분리하여 동시 수정 충돌을 줄임.
- npm run verify 통과 및 관련 모바일·데스크톱 브라우저 흐름 확인.
- 독립 QA의 확인된 주요 결함 해결, 미검증 사항과 남은 제한을 문서화.

## 제안 분담
메인: 구조 경계와 통합. story-frontend: 할당한 UI/상태 개선. story-qa: 독립 검토. story-narrative는 서사 개선까지 범위를 확장할 때만 투입. story-backend는 호출하지 않음.

## 사용자와 결정할 내용
첫 목표를 안정화 중심으로 할지, 시각 디자인·서사 개선까지 포함할지 결정한다. 필요하면 토큰 예산을 사용자와 별도로 정한다. 예산은 현재 미설정. 목표에 동의하고 실행을 요청하면 그때 목표를 생성하고 시작한다.
